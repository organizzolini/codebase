# Fixing Each Tool

Read the tool's configuration before proposing a fix, and fix the cause: never a disable comment, a loosened compiler option, an ignore entry added only to pass, or a raised limit.

## Manual Fixes

| Failing target                               | What to do                                                                                                                                                                                                                                                                                                                              |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `typecheck`                                  | Read the errors. Use optional chaining for index access (`array[0]?.property`), never `any`, explicit return types, and `import type` for type-only imports. See [write-typescript](../../write-typescript/SKILL.md).                                                                                                                   |
| `type-coverage`                              | Type the untyped expressions it lists; `typecheck` passing does not clear it.                                                                                                                                                                                                                                                           |
| `spell-check`                                | Fix or reword the word first. Add a genuine domain term to its dictionary per [spell-check](../../spell-check/SKILL.md); never add a word to pass.                                                                                                                                                                                      |
| `markdown-lint` `MD024/no-duplicate-heading` | If the duplicated content is identical, remove one block; if it differs, rename one heading to something specific.                                                                                                                                                                                                                      |
| `markdown-lint` `MD060/table-column-style`   | Match the table to its own header row's style: align every pipe, or none.                                                                                                                                                                                                                                                               |
| `knip`, `fallow-dead-code`                   | Remove the unused export, file, or dependency. An exception that is genuinely warranted goes in both configurations.                                                                                                                                                                                                                    |
| `vulture`                                    | Remove the unused code; whitelist only code reached in ways vulture cannot see, such as framework callbacks.                                                                                                                                                                                                                            |
| `lockfile`                                   | `pnpm install`, then review `pnpm-lock.yaml`; revert a rewritten `projects/JimmyPaolini` entry rather than reconciling it.                                                                                                                                                                                                              |
| `commitlint`                                 | Amend the message to the [commit-code](../../commit-code/SKILL.md) format.                                                                                                                                                                                                                                                              |
| `validate-branch-name`                       | Rename with [checkout-branch](../../checkout-branch/SKILL.md#rename-a-branch).                                                                                                                                                                                                                                                          |
| `guard-code` gates                           | Each IC-suite gate has its own triage skill: [callidescope-triage](../../callidescope-triage/SKILL.md), [codependix-triage](../../codependix-triage/SKILL.md), [codometer-triage](../../codometer-triage/SKILL.md), [coinagerie-triage](../../coinagerie-triage/SKILL.md), [conformetry-validate](../../conformetry-validate/SKILL.md). |

## Sync Checks

Each derivation is its own Nx target, run directly; there is no `sync-*` target or aggregate besides `integration:start`. A failure means a source of truth changed without its counterpart, so run the `write` configuration and review what it rewrites.

| Check                                    | Fix with `:write` | Keeps in step                                                                                                                                                                         |
| ---------------------------------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `integration:conventional-config`        | Yes               | [conventional.config.cjs](../../../../configuration/repository/conventional.config.cjs) with `.vscode/settings.json`, the issue template, CONTRIBUTING.md, and the commit-code tables |
| `integration:devcontainer-configuration` | Yes               | The cloud and local devcontainer configurations                                                                                                                                       |
| `compliance:pull-request-template`       | Yes               | [PULL_REQUEST_TEMPLATE.md](../../../../.github/PULL_REQUEST_TEMPLATE.md) with the create-pull-request skill                                                                           |
| `integration:skill-exclusions`           | Yes               | The vendored-skill exclusion blocks with `skills-lock.json`                                                                                                                           |
| `integration:vscode-extensions`          | Yes               | `.vscode/extensions.json` with both devcontainers                                                                                                                                     |
| `integration:readme-projects`            | No: add the row   | The root README's project table with the workspace                                                                                                                                    |
| `integration:skill-descriptions`         | No: shorten it    | Each authored description within 64 words, all within 12,500 characters                                                                                                               |
| `persistence:typeorm-migration-sql`      | Yes               | Migration SQL with the entities                                                                                                                                                       |

Every derivation at once: `pnpm exec nx run-many --targets=conventional-config,devcontainer-configuration,pull-request-template,skill-exclusions --configuration=write`. Codependix README blocks have no branch check: `nx run configuration:codependix:write` publishes them from the default branch.

## Common Symptoms

| Symptom                                   | Cause                        | Fix                                                                                   |
| ----------------------------------------- | ---------------------------- | ------------------------------------------------------------------------------------- |
| `Unexpected token`, `Expected whitespace` | Format check failed          | `nx affected --target=oxfmt,prettier --configuration=write`                           |
| `error ... @typescript-eslint/...`        | ESLint rule violation        | `nx affected --target=eslint,oxlint --configuration=write`, then fix the rest by hand |
| `Type 'X' is not assignable to 'Y'`       | Type error                   | Fix the code; never loosen `tsconfig.json`                                            |
| `Unknown word`                            | cspell                       | See `spell-check` above                                                               |
| `lockfile needs update`                   | `pnpm-lock.yaml` out of sync | `pnpm install`                                                                        |
| `subject may not be empty`                | commitlint                   | Amend the message                                                                     |
| `Unused export`                           | knip                         | Remove the export                                                                     |
